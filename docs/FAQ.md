## 安装与环境

**Q：需要 `npm install` 吗？**

不需要。QQUltra 零运行时依赖，数据库用 Node 内置的 `node:sqlite`，网络用内置 `fetch` / `WebSocket`。
只要 Node 版本够，`git clone` 之后就能直接跑。

**Q：Node 版本要求？**

≥ 22.5，因为要用 `node:sqlite`。用 `node bin/qqultra.js version` 可以看到当前 Node 版本。

**Q：想先看看效果，但不想配 QQ 环境。**

```bash
node bin/qqultra.js demo
```

用内存库 + 模拟适配器跑完整链路，不碰任何外部服务。

**Q：能跑在 Windows 上吗？**

可以（Node 跨平台）。常驻运行建议用 systemd / Docker（见 [DEPLOY.md](DEPLOY.md)），
Windows 可以用计划任务或 NSSM 之类的服务包装器。

## 接入与连接

**Q：一定要用 NapCat 吗？**

不用。任何实现 OneBot 11 的协议端都行：NapCat、Lagrange、LLOneBot、go-cqhttp。
NapCat 的优势是能直接装进 PC 端 QQ，和「在 QQ 里用」的定位最贴。

**Q：启动即 `无法连接 OneBot 服务端`。**

按顺序查：协议端是否已开启 OneBot 11 的 **WebSocket 服务端**（不是反向 WS）→
`onebot.wsUrl` 的端口是否与协议端一致 → `accessToken` 是否两边相同。
用 `node bin/qqultra.js inspect` 确认进程真正读到的地址。

**Q：连上了但收不到消息。**

- 协议端是否上报 `message` 事件；
- 该群是否被停用（`/status` 会点出来）；
- 机器人是否在群里（不在群里收不到该群消息）。

**Q：机器人没有公网入口，能用吗？**

用反向模式：`onebot.mode = "reverse"`，QQUltra 监听端口等协议端连进来。
Docker 里记得映射端口（`-p 8642:8642`）。

**Q：日志一直刷「动作 … 超时」。**

协议端响应慢或连接已断。先看协议端日志，再确认网络与超时设置。
QQUltra 侧不会因此崩溃，但处置可能降级。

**Q：重连会不会重复处理消息？**

不会重复入库。QQUltra 按 `(群号, message_id)` 去重（见下一条）。

## 指令与权限

**Q：管理员指令提示「需要管理员权限」。**

- 群里：确认发送者在群里确实是管理员或群主；
- 私聊：私聊没有群角色，必须把自己的 QQ 号写进 `permission.whiteList`。

**Q：私聊 `/stats` 说「这是群内指令」。**

私聊拿不到群号，硬跑会返回一份「群 null」的假报告，所以直接拒绝并提示去群里用。
私聊可用的是 `/help` `/about` `/ping` `/status` `/panel` `/ai` `/ai-stats` `/ai-reset`。

**Q：`/purge` 提示需要权限，但我是群主。**

`/purge` 的级别是 **owner**。私聊里没有群主概念，只能靠白名单。

**Q：参数写错会不会被当成故障？**

不会。用户输入错误会回 `⚠️ 未知统计周期「季度」，可选：today / week / month / all` 这类提示；
只有真正的内部异常才显示「指令执行失败」。

**Q：`/violations --n 2` 只显示 1 条？**

0.3.0 之前的版本会把 `--n 2` 解析成 `flags.n = true`，而 `Number(true) === 1`，
于是静默只显示 1 条。升级即可，现在两种写法（`--n=2` 与 `--n 2`）都支持。

## 统计与数据

**Q：统计数字比实际偏大。**

0.3.0 之前的版本会被协议端重放的消息重复计数：NapCat / Lagrange 在重连、拉历史时会把同一条消息重放一次，
重放的消息业务上完全合法，但会让总消息数、活跃榜、时段分布均匀偏大。

现在按 `(group_id, message_id)` 唯一索引去重；老库升级时迁移会自动清掉历史重复行。

**Q：活跃榜上的人不是最活跃的？**

活跃榜**排除指令消息**：`/stats` 这类操作是对机器人下的指令，不是群成员之间的交流，
计入活跃会让「最活跃的人」变成最常查数据的人。机器人自己的消息也不入库。

**Q：`/stats today` 少了刚发的一条。**

0.3.0 之前周期上界用的是 `until = now`，同毫秒入库的消息会被漏掉。现在上界取 `now + 1` 的右开区间。

**Q：`/whois` 显示「累计发言 12 条」，但明细里一条都查不到。**

幽灵成员：老版本的 `/purge` 只删明细不清成员汇总。现在清理会同步清掉这类行。

**Q：保留策略到底跑了没有？**

`/status` 的「数据保留」自检项会显示上次执行时间与生效天数，
超期未跑会变成 ⚠️。0.3.0 之前这两个键从来没被写入过，所以那一项永远不显示。

**Q：数据存哪？能改路径吗？**

默认 `data/qqultra.db`（SQLite 单文件）。改 `dataFile` 或 `QQU_DATAFILE`。备份见 [README「数据」](../README.md#数据)。

## 检测与风控

**Q：机器人明明在线，为什么不撤回 / 不踢人？**

机器人需要**群管理员权限**。权限不足时不会崩溃，但处置会降级为群内提醒，
并在违规记录里标记 `degraded`——**且不计入升级阶梯**（罚不成功不该变本加厉）。

**Q：一次刷屏，为什么只处理了一次？**

设计如此：一次刷屏会连续命中多条消息，QQUltra 把它折叠成一个事件
（默认 60 秒窗口）。不折叠的话一次刷屏就能把处罚从禁言顶到踢出。

**Q：复读会被踢人吗？**

不会。复读的默认动作是警告，升级上限是**禁言**。每类违规都有自己的升级上限，
只有刷屏和广告能累犯加重到踢出。

**Q：管理员发的广告为什么没被处理？**

群主与管理员默认在 `detect.punish.trustedRoles` 里，永不被自动处罚，但**会留痕**
（`/violations` 里标「仅记录，未处置」）。留痕是为了能回答「机器人当时看到了吗」。

这类豁免命中**不计入风控统计**，否则管理员说一句广告口径的话就会把异常预警打到触发。
预警一旦变成噪音源，管理员的第一反应是关掉整个功能。

**Q：`/rule add` 提示成功了，但规则从不生效。**

0.3.0 之前不校验类型与正则，`keywrod` 拼错、正则未闭合都会「✅ 已添加规则」。
现在添加时当场校验，非法输入直接报错。用 `/rules audit` 可以查出历史上留下的空转规则。

**Q：`加 微-信 123` 这种写法能绕过检测吗？**

不能。所有匹配都跑在归一化文本上：全角会被转半角、零宽字符会被剥离、
常见分隔符会被去掉，所以这类绕过写法都会命中。

**Q：广告检测会不会误伤正常聊天？**

广告判定要求「联系方式 **+** 引流动词」同时命中，而不是单看联系方式。
只发一个微信号、没有引流意图的消息不会触发。

**Q：机器人不知道入群时间，新人广告从不触发。**

0.3.0 之前 `first_seen` 只在发言时写入，「入群时间」其实是「首次发言时间」，
导致新人广告检测静默失效。现在入群时间由 `group_increase` 通知独立记录——
需要协议端上报该通知，且机器人在群内。

**Q：异常预警刷屏了。**

调高阈值 `/alert threshold 10`，或关掉 `/alert off`。
预警本身有 30 分钟冷却，同群不会连续提醒。

## AI

**Q：`/ai` 不回话。**

按顺序查：

1. `ai.enabled` 是否为 `true`（配置文件或 `QQU_AI__ENABLED`）
2. `ai.apiKey` 是否已填
3. 群内触发方式是否为 `mention`（默认要 @ 机器人）；私聊不需要触发词
4. 用 `QQU_LOGLEVEL=debug` 启动看上游原始错误（常见为 key 无效、余额不足、`baseUrl` 写错）

如果 AI 未启用，`/ai` 会明确回复「AI 功能未启用」而不是静默不答。

**Q：能用通义 / 自建模型吗？**

可以。QQUltra 只依赖 OpenAI 兼容的 `/chat/completions` 接口，
改 `baseUrl` 与 `model` 即可；自建 vLLM、Ollama（OpenAI 兼容模式）同样适用。

**Q：AI 会编造群活跃数据吗？**

`/ai-stats` 会把真实统计数字注入提示词，并要求模型以此为准。
不过模型仍可能跑偏，重要结论请以 `/stats` 的数字为准。

**Q：AI 会不会暴露群里的隐私？**

AI 回复时只发送当前会话上下文与提问；`/ai` 是点名提问，不带群上下文。
不采集 IP 或客户端信息，数据只落本地 SQLite，不外传。不想要 AI 可以 `/config set ai.enabled false`。

**Q：机器人偶尔把 AI 回复当上下文循环引用？**

机器人自身消息不入库，也不会成为上下文。会话记忆按 `maxKeep` 裁剪，不会无限膨胀。

## 词云与面板

**Q：词云发的是文本不是图。**

协议端不支持发送本地文件时会自动退回文本词云（日志 debug 级有记录），属预期降级。
面板 `--img` 同理。

**Q：词云里有 `/wordcloud`、`--top` 这种词。**

0.3.0 之前会把指令当语料。现在 `/wordcloud` 与 `/history` 都会排除指令消息。

**Q：标题说 20 个词，图里只有 12 个。**

螺旋布局在画布内找不到空位时**放弃这个词**而不是叠上去——重叠的词云是错的，少两个词只是不够满。
标题会写明「布局容纳 N 个（M 个过长未绘入）」。

**Q：临时目录里有 `qqu-*.svg`。**

0.3.0 之前出图文件永不删除（`/wordcloud` 与 `/panel --img` 会在 tmpdir 无限堆积）。
现在有 10 分钟 TTL + 写入前回收 + 数量兜底；若仍在堆积，检查进程是否被 `kill -9`（跳过了退出清理）。

**Q：面板里少了几条指令。**

普通成员看不到管理项，属预期（`/panel` 按权限过滤）。用管理员账号看，或私聊机器人看完整版。

## 升级与迁移

**Q：升级会不会丢数据？**

不会。迁移只做增量（`MIGRATIONS` 数组追加，已发布的版本不改），
升级前建议备份 `.db` 文件（含 `-wal`、`-shm`）。

**Q：老库升级会不会起不来？**

0.3.0 的迁移会先清理历史重复行再建唯一索引——不清就建不上，老库会直接起不来。
这一步是自动的，但库越大耗时越长；超大库建议先备份再升级。

**Q：怎么看当前版本？**

```bash
node bin/qqultra.js version
```

变更历史见 [CHANGELOG.md](../CHANGELOG.md)，每条都写了「原来错在哪」。

## 隐私与安全

**Q：会收集什么数据？**

只存群号、QQ 号、昵称与消息文本。不采集 IP、设备或客户端信息；机器人自身消息不入库。

**Q：能关掉统计吗？**

能。全局 `stats.enabled: false`，或按群 `/config set stats.enabled false`；
已有数据用 `/purge <天数>` 清理。

**Q：反向模式暴露端口安全吗？**

必须设置 `accessToken`，并且只对协议端开放，不要暴露到公网。
鉴权失败会以 `4001 unauthorized` 关闭连接并记日志。

**Q：白名单能做什么？**

被列入 `permission.whiteList` 的 QQ 号可以私聊执行管理指令，且在群里不会被自动处罚。
只加你信任的运维账号。

**Q：发现安全问题怎么报？**

优先走私密渠道联系作者（见 [README 作者](../README.md#作者)），不要在公开 Issue 里贴可利用细节。

**Q：用这个机器人出了问题，作者负责吗？**

不负责。本软件按「现状」（AS IS）提供，**作者、贡献者与分发者不对任何直接、间接或后果性损失承担责任**，
包括数据丢失、账号被限制或封禁、群聊关系受损、业务中断等。完整条款见
[DISCLAIMER.md](../DISCLAIMER.md)，群内发 `/disclaimer` 也能看到。

**Q：我需要在群里告知成员吗？**

需要。把机器人放进**他人所在的群**之前，应取得群主与成员的必要授权，
并确保统计、检测与自动处置行为符合当地法律、平台规则与群规。
隐私边界见 README「隐私边界」一节，或见 [DISCLAIMER.md 第五节](../DISCLAIMER.md#五数据与隐私)。

**Q：检测误判把人禁言了，谁担责？**

自动化检测存在**误判与漏判**，这是任何规则/模型方案的固有代价，作者不保证判定准确。
请在 `/rules` 里调阈值、优先用提醒而非直接处置，并且**不要把机器人判定当作处罚的唯一依据**。
因误判产生的后果由部署与使用者承担。

**Q：群内怎么快速查看声明？**

- `/disclaimer` —— 简版（默认，适合群里阅读）
- `/disclaimer full` —— 完整七节条款
- 命令行 `qqultra disclaimer` —— 终端完整输出
- 仓库 [DISCLAIMER.md](../DISCLAIMER.md) —— 权威版本

**Q：本地数据要是丢了能找回吗？**

不能。数据只存在你自己部署环境的 SQLite 文件里，作者既接触不到也没有备份。
请自行备份（见 README「运维与数据」的 `.backup` 示例），并用 `stats.retentionDays` 与 `/purge` 控制保留期限。
