# 使用手册

面向群主、管理员与日常使用者。所有指令都是**群内发消息**或**私聊机器人**，
PC 端 QQ 的聊天窗口就是操作台。

## 三条使用路径

| 路径 | 怎么做 | 适合 |
| --- | --- | --- |
| **群内** | 直接在群里发指令，机器人回复在群里 | 公开的统计、榜单、给全群看的结论 |
| **私聊** | PC 端 QQ 好友列表里找机器人直接对话 | 不想刷屏的运维操作，逐条排查 |
| **CLI** | `node bin/qqultra.js <命令>` | 服务器上排障、离线看历史数据 |

`/panel` 是最快的入口：一屏列出所有可用指令，按你的权限过滤，复制粘贴即可执行。
`/panel --img` 会渲染成图文卡片，长清单不会被 PC 端 QQ 折叠。

## 权限模型

| 级别 | 谁能用 | 包含的指令 |
| --- | --- | --- |
| 所有人 | 群内任何成员 | `/help` `/panel` `/status` `/about` `/ping`、全部统计数据与洞察 |
| 管理员 | 群管理员 / 群主 | `/violations` `/alert` `/rule` `/config` `/subscribe` `/approve` |
| 群主 | 仅群主 | `/purge` |

**私聊是例外，也是刻意的**：私聊里没有群角色，所有管理指令只认
`permission.whiteList` 里的 QQ 号：

```json
{ "permission": { "whiteList": ["你的QQ号"] } }
```

否则任何人都能私聊机器人执行 `/purge` 清库。想私聊运维，就必须先显式把自己加进白名单。

> 私聊里执行**群维度**指令（如 `/stats`）会被直接拒绝并提示去群里用——
> 因为它拿不到群号，硬跑只会返回一份「群 null」的假报告。
> 私聊可用的是：`/help` `/about` `/ping` `/status` `/panel` `/ai` `/ai-stats` `/ai-reset`。

## 通用约定

- **前缀**：默认 `/`（当前版本固定，见 [CONFIG.md](CONFIG.md)）。
- **中文别名**：`/菜单`＝`/help`，`/统计`＝`/stats`，`/排行`＝`/活跃榜`＝`/rank`，`/我的`＝`/me`，
  `/群规`＝`/规则`＝`/rules`，`/违规`＝`/记录`＝`/violations`，`/历史`＝`/history`，`/词云`＝`/wordcloud`，
  `/预警`＝`/alert`，`/订阅`、`/退订`、`/状态`、`/面板`，以及 `/ai统计`、`/ai记忆`；
  另有 `/沉默`＝`/silent`，`/趋势`＝`/话题`＝`/trend`，`/新人`＝`/newcomers`，`/总览`＝`/活跃总览`＝`/vibe`。
- **周期参数**支持英文与中文：`/stats week` ＝ `/stats 本周` ＝ `/stats 周`。
- **旗标两种写法都行**：`/stats --top=5` 与 `/stats --top 5` 等价；`--img` 这类开关直接写。
- **参数写错会被告知用法**，不会报「指令执行失败」：

  ```
  ⚠️ 未知统计周期「季度」，可选：today / week / month / all
  ```

- **指令不算活跃**：`/stats`、`/panel` 这类操作会入库（便于审计），但不计入活跃榜、活跃人数、时段分布与词云语料。

## 指令手册

### 面板与状态

| 指令 | 说明 |
| --- | --- |
| `/help` | 指令一览，分组列出 |
| `/panel [--img]` | 管理面板，按权限过滤；`--img` 出图文卡片 |
| `/status` | 运行状态 + 健康自检：群状态、数据流入、检测开关、连接新鲜度、数据保留 |
| `/about` | 版本、作者与各渠道 |
| `/ping` | 存活检查，返回运行时长 |

`/status` 是排障第一站：掉线、权限缺失、检测被人关掉、保留策略超期未跑，都会在这里被点出来。

### 统计与榜单

| 指令 | 参数 | 说明 |
| --- | --- | --- |
| `/stats` | `[周期] [--top=N]` | 消息量、活跃人数、环比、活跃榜 |
| `/rank` | `[周期] [--top=N]` | 只输出活跃榜 |
| `/wordcloud` | `[周期] [--img]` | 词云图卡（协议端不支持发图时自动退回文本） |
| `/me` | — | 我的发言档案：今日/本周/本月/累计、排名、活跃时段 |
| `/whois` | `@某人` 或 `QQ号` | 查他人档案 |
| `/history` | `[@某人] [--n=5]` | 最近发言回顾；不带 @ 时给近 24 小时最新发言 |

周期可选 `today`（默认）/ `week` / `month` / `all`，也接受 `本周`、`周`、`月`、`全部`、`累计` 等写法（大小写不敏感）。

`--top` 与 `--n` 都有上限（分别 50 / 20 / 30），避免一条消息被撑爆。

### 运营洞察

| 指令 | 默认窗口 | 说明 |
| --- | --- | --- |
| `/vibe` | 今日/本周/本月 | 活跃总览 + 周活跃占比 + 一句判断 |
| `/silent [天数]` | 14 天 | 累计发言 ≥10 条、但最近 N 天没说话的人 |
| `/trend [天数]` | 7 天 | 近 N 天 vs 前 N 天，分「变热 / 新话题 / 变冷 / 已消失」 |
| `/newcomers [天数]` | 7 天 | 新成员观察：区分「潜水新成员」与「正常新人」 |
| `/rules audit` | — | 挑出「启用却从未命中」的规则 |

命令行等价入口（读本地库，不需要 QQ 环境）：

```bash
node bin/qqultra.js insight <群号>
```

**怎么读这些结论**

- `/vibe` 的**活跃占比**才是关键：群里 200 人但只有 5 个人说话，和 20 人里 15 个人说话，是完全不同的两个群。
- `/silent` 设了「历史发言 ≥10 条」门槛：只冒过一两次泡的人不算流失，曾经活跃的人突然安静才值得有人去问一句。
- `/trend` 比的是**占比**不是次数：群消息量本身波动很大（节假日能翻倍），比次数会把「群变热闹」误读成「这个话题变热」。
- `/rules audit` 列出从未命中的规则。它们要么本来就多余，要么模式写错了——一条写坏的正则只会安静地躺着等一次误伤。

### 风控与规则

| 指令 | 权限 | 说明 |
| --- | --- | --- |
| `/rules` | 所有人 | 查看自定义规则、命中次数、启用状态 |
| `/rules audit` | 所有人 | 规则命中效果评估 |
| `/violations [--n=10]` | 管理员 | 最近违规记录，**按事件聚合**（一次违规一行） |
| `/alert` | 管理员 | 查看预警状态、阈值与当前窗口命中数 |
| `/alert on` / `/alert off` | 管理员 | 开关异常预警 |
| `/alert threshold 10` | 管理员 | 改阈值（次 / 10 分钟） |
| `/rule add <keyword\|regex> <内容> [--action=warn\|mute\|kick]` | 管理员 | 新增自定义规则 |
| `/rule del <id>` | 管理员 | 删除规则 |
| `/rule on <id>` / `/rule off <id>` | 管理员 | 启用 / 停用规则 |

新增规则示例：

```
/rule add keyword 违禁词 --action=mute
/rule add regex 广告\s*位 --action=warn
```

类型与正则会在添加时当场校验：`keywrod` 这类拼错的类型、未闭合的正则都会被直接拒绝，
而不是「✅ 已添加规则」然后永不生效。

`/violations` 里的标记含义：

| 标记 | 含义 |
| --- | --- |
| `→mute` / `→kick` / `→warn` | 实际执行的处置 |
| `（仅记录，未处置）` | 白名单角色命中，或本群只检测不处罚 |
| 标题写「其中 N 次豁免」 | 这次列表里既有真处置也有豁免 |

### 群配置

| 指令 | 权限 | 说明 |
| --- | --- | --- |
| `/config` | 管理员 | 本群配置摘要 |
| `/config keys` | 管理员 | 列出全部可配置项 |
| `/config set <键> <值>` | 管理员 | 修改本群配置 |

常用示例：

```
/config set ai.trigger prefix              # AI 改用前缀触发
/config set ai.enabled false               # 关掉本群 AI
/config set ai.prefix /bot                 # 改前缀
/config set detect.enabled false           # 关掉本群检测（只统计）
/config set detect.punish.enabled false    # 只检测不处罚
/config set detect.punish.muteSeconds 300  # 禁言时长
/config set alert.enabled false            # 关掉异常预警
/config set alert.threshold 10             # 阈值调到 10 次/10 分钟
/config set welcome.enabled true           # 开启入群欢迎
/config set welcome.text 欢迎 {at} 进群～
/config set stats.enabled false            # 本群不统计
```

配置**按群独立**，只影响当前群。键名不在白名单内会被拒绝，不会污染数据库。

### AI

| 指令 | 说明 |
| --- | --- |
| `/ai <问题>` | 提问。群里默认需 @ 机器人；私聊直接发 |
| `/ai-stats [周期] [问题]` | 让 AI 基于真实统计数字解读并给建议 |
| `/ai-reset` | 清空本会话记忆（群里清本群，私聊清自己） |

`/ai-stats` 把真实统计注入提示词并要求模型以此为准——**不会编造群活跃数据**。
不带问题时用默认提问「总结本群活跃情况并给出一条改进建议」。

`/ai` 是「点名提问」，不注入群上下文、也不写回会话记忆；群里默认的接话模式（`ai.trigger = mention`）才会带上下文。

AI 未启用时 `/ai` 会明确回复「AI 功能未启用（请在配置中设置 ai.enabled 与 ai.apiKey）」，不会静默不答。

### 入群审核

| 指令 | 权限 | 说明 |
| --- | --- | --- |
| `/approve <flag>` | 管理员 | 通过入群申请 |
| `/reject <flag>` | 管理员 | 拒绝入群申请 |

默认**人工审核**：收到申请时日志里打印 `待审核入群申请 group=... user=... flag=...`，
管理员用 `/approve <flag>` 处理。想自动放行：

```
/config set antispam.autoApprove true
```

> 需要协议端上报 `request` 事件，且机器人在群内有审核权限。

### 数据清理

| 指令 | 权限 | 说明 |
| --- | --- | --- |
| `/purge <天数>` | 群主 | 删除 N 天前的消息明细、违规记录与空成员汇总 |

```bash
node bin/qqultra.js purge 30      # 命令行等价操作
```

清理会同步清掉「明细已删但汇总仍在」的成员行，否则 `/whois` 会一直展出查不到明细的幽灵成员。

## 场景配方

**新群开荒（第 1 天）**

```
/status                     # 确认连接、检测、统计都正常
/config set welcome.enabled true
/config set welcome.text 欢迎 {at} 加入本群，请先看群公告～
/config set alert.threshold 8
/subscribe                  # 订阅每日简报
/rule add keyword 代刷 --action=mute
```

**每周例行体检**

```
/vibe                       # 群还活着吗？活跃占比多少？
/silent 14                  # 谁悄悄不说话了
/trend 7                    # 话题在升还是在降
/rules audit                # 哪些规则在空转
/violations --n 20          # 风控有没有漏
/subscribe                  # 每天自动收简报（订阅一次即可）
```

**推广期（垃圾信息高发）**

```
/config set detect.punish.enabled true
/config set alert.threshold 3          # 更敏感
/alert threshold 3
/rule add regex 加\s*我.*(微信|QQ)     # 反绕过靠归一化，不用怕空格
/violations --n 30                     # 回看命中效果
```

**AI 答疑群**

```
/config set ai.trigger all             # 所有消息都交给 AI
/config set ai.maxReplyLength 300      # 限制长度，免得刷屏
/ai-stats week 本周大家主要在聊什么？    # 用真实数据总结
```

**群太吵，先安静一阵**

```
/config set ai.enabled false
/config set alert.enabled false
/config set detect.punish.enabled false   # 只记录不处理
```

## 输出里的细节含义

**统计里的数字**

- 「活跃榜」只统计**非指令**消息；机器人自己的消息不入库。
- 环比是与**等长**上一周期比较（今日 vs 昨日、本周 vs 上周），不是「与上月同日」。
- 时段分布按消息本地时间落格，`/me` 里的「活跃时段」是发言最多的那几个小时。

**判定语气**

| 输出 | 含义 |
| --- | --- |
| ✅ | 操作成功 |
| ⚠️ | 参数用错，附带正确用法 |
| ⛔ | 权限不足 |
| `指令执行失败：…` | 真的出错了（内部异常），建议连同日志一起看 |
| `（仅记录，未处置）` | 命中但按策略放行，不是故障 |
| `/silent` 返回空 | 「没有这样的人」是结论，不是故障 |
| `/trend` 说「上一周期无数据」 | 该周期确实没有明细，或已被保留策略清理 |

**词云**

- 标题里的「布局容纳 N 个（M 个过长未绘入）」是实话：宁可少画也不重叠，重叠的词云是错的。
- 协议端不支持发本地文件时会自动退回文本词云，日志 debug 级有记录。
